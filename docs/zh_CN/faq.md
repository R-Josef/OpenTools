# 常见问题

## 便携包为什么仍需要完整目录？

`OpenTools.exe` 只是启动器。它需要 `runtime/` 提供 Java、`app/` 提供程序，并从
`tools/` 查找外部程序。单独复制 EXE 会失去这些依赖。

## 是否需要安装 Java 或 conda？

Windows 便携包不需要。通用 JAR 需要 Java 21；两类发布物都不要求 conda。

## 为什么外部工具显示缺失？

先运行 Settings 中的 External Tools Check。如果使用便携包，确认 `tools/` 未删除；
开发者版可设置对应 `OPENTOOLS_*` 变量或在任务中选择路径。也检查可执行文件是否
与当前操作系统和架构兼容。

## 为什么 BLAST 第一次比后续慢？

OpenTools 会按 subject 哈希、BLAST 版本、程序和数据库类型构建可复用数据库。
首次构建较慢；后续若缓存键匹配会复用。缓存受大小和条目上限约束。

## 为什么 VCF 输出没有索引？

索引要求 `##contig` 字典和字典顺序记录。压缩 VCF 使用 TBI，BCF 使用 CSI；
普通未压缩 VCF 默认不索引。

## 为什么 CRAM 任务要求参考 FASTA？

CRAM 可能只保存参考差异。若参考未内嵌，读取或写出依赖必须提供匹配的 reference。

## AUTO 并行为什么有时仍是单线程？

`threads=0` 是保守 AUTO，不是强制并行。小文件或顺序 I/O 瓶颈下自动路径可能选择
一个 worker；`threads=1` 明确关闭并行。最终渲染、全局表和部分注释操作仍保持顺序。

## 应用内文档是否需要联网？

不需要。文档和资源随 JAR/便携包分发，渲染器不加载远程图片或脚本。外部网页链接
仅交给系统浏览器。

## 插件是否安全沙箱？

不是。插件默认禁用，启用后仍可作为受信任代码访问当前用户权限。只启用可信来源，
并在启用前检查 API、依赖和能力声明。

## 如何报告问题？

提供 OpenTools 版本、任务 ID、操作系统、错误码、可复现最小输入和脱敏后的
`manifest.json`/`run.log`。不要提交密钥、token 或未经许可的研究数据。
